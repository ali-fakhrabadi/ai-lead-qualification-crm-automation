# Security and privacy controls

The system handles personal data (names, work emails, inquiry text) and talks to a model, a CRM
and n8n. Controls by area; the threats they answer are in [threat-model.md](threat-model.md).

## Access

- **Operators** sign in with email + password (Argon2id). Access tokens are JWT (HS256, 15
  minutes); refresh tokens are random, stored hashed, rotated on every use, and **reuse of an old
  refresh token revokes the whole family** (stolen-token detection). Login is rate limited per IP
  and per email.
- **Roles:** `viewer` (read only), `operator` (decisions, drafts, retries, duplicate review),
  `admin` (users). The role is read from the database on every request, so a demotion takes effect
  at once. Denied attempts are audited (`authz.denied`).
- **Internal API** (`/internal/v1/*`, used by n8n): a separate service token, compared in
  constant time; nginx returns `404` for `/internal/` from outside, so it is reachable only on the
  internal Docker network.
- **Partner webhooks:** HMAC-SHA256 over `timestamp.body` with a per-source secret, 300 s
  tolerance, constant-time comparison; unknown source `404`, bad or expired signature `401`;
  rate limited per IP and per source; rejections audited without the body.
- **Dispatcher → n8n:** HS256 token with issuer, audience, 5-minute expiry, the event id and the
  SHA-256 of the exact payload; n8n verifies all of them.
- **n8n editor** on `127.0.0.1` only; owner managed by environment (no claimable setup page).
- **Fault injection** (tests and benchmark only) requires `LEAD_FAULT_INJECTION_ENABLED`, a
  separate admin token, and is refused when `LEAD_ENVIRONMENT=production`.

## Data minimisation and the model

- The model receives business fields only: interest, message, company, job title, company
  domain, country. **Never** the name, email or phone.
- Lead text is fenced as untrusted data; a pattern check flags instruction-like text and forces
  review whatever the model answers; the model has no tools, no browsing, no write access. Its
  output is validated against a strict schema, evidence quotes must occur in the message, and
  the score and decision come from deterministic rules.
- Default provider: **Ollama on a host you control**: no lead data leaves your network. With
  `LEAD_LLM_PROVIDER=openai`, the business fields above are sent to OpenAI under your account's
  terms; the setting is explicit and every assessment records the provider and model.
- The CRM receives the contact fields, company and a qualification note, never the raw message.

## Outbound communication

- Follow-ups are **drafts**. Only a person can approve one; approval is audited with the user,
  time and note; edits are audited.
- Delivery mode `sink` (default) sends to the local Mailpit only. Real SMTP needs
  `LEAD_DELIVERY_MODE=smtp` **and** `LEAD_DELIVERY_ALLOW_REAL_RECIPIENTS=true` (refused otherwise
  at start-up). Approval is blocked while a duplicate review is open on the lead.
- n8n's only outbound mail is the operator notification, to the configured operators' mailbox.

## Input handling

- Strict Pydantic models with length limits; a 32 KB request body limit in FastAPI and 64 KB in
  nginx (`413`); emails normalised and IP-literal domains refused; websites stored as a host name
  and **never fetched** (no SSRF through lead data).
- Validation errors name the field and the problem, never echo the value.
- The React app renders lead text as text (no `dangerouslySetInnerHTML`); a strict CSP
  (`default-src 'self'`, no inline scripts, `frame-ancestors 'none'`), `X-Frame-Options: DENY`,
  `nosniff`, `Referrer-Policy: no-referrer`, COOP.
- Honeypot field on the public form; public form rate limited per IP.
- n8n SSRF protection with an allow-list (`api`, `mailpit`).

## Secrets

- Generated by `scripts/init-secrets.sh` into `secrets/` (git-ignored, directory `0700`) and
  mounted as Docker secrets (`*_FILE` settings); never in `.env`, images, logs or the repository.
- Production start-up refuses short or missing secrets.
- n8n credentials are created from secrets by the setup service and stored encrypted with
  `N8N_ENCRYPTION_KEY`; workflow exports contain only credential ids. **Back up the encryption
  key** together with the n8n database, or the stored credentials cannot be decrypted.
- CI scans the full history with gitleaks.

## Containers and network

- Every service is `read_only`, `cap_drop: [ALL]`, `no-new-privileges`, non-root, with tmpfs for
  scratch space and CPU/memory limits.
- Two networks: `backend` (internal: no route out) for PostgreSQL, API, n8n, runners, demo CRM,
  Mailpit; `edge` only for what must be reachable. Published ports: the web entry point (bind
  address configurable), and the n8n editor and Mailpit UI on `127.0.0.1`. PostgreSQL is never
  published.
- Least-privilege database roles: `lead_owner` (migrations), `lead_app` (data only, no DDL),
  `n8n` and `crm_demo` with their own databases and no access to `leads`.
- Images pinned by digest; dependencies locked with hashes; pip-audit, npm audit and Trivy in CI.

## Logging, audit, retention

- Structured JSON logs with request and correlation ids; emails masked (`m***@domain`), no
  message bodies, no tokens.
- Audit log of decisions, overrides, edits, approvals, deliveries, retries, duplicate
  resolutions, rejected webhooks and denied access.
- Consent to be contacted is required and stored with the consent text version; marketing consent
  is separate and optional.
- `python -m app.cli purge` deletes closed leads older than `LEAD_RETENTION_DAYS` (default 365);
  an admin can delete a lead and its records (audited) for erasure requests.

## Not covered (see [limitations.md](limitations.md))

No HTTPS in the lab deployment (no domain): it is LAN-only and must not be exposed to the
internet as is. No SSO/MFA. Prompt-injection detection is a pattern check plus structural
defences, not a guarantee; the guarantee is that no injected text can trigger an action without a
person.
